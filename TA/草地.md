Alpha Clip（ Alpha 测试 / Alpha Testing）是计算机图形学中用于处理透明度剪裁的技术。它常用于绘制草地、树叶、铁丝网等需要透空但结构复杂的模型。

---

**1. Alpha Clip 是什么**

Alpha Clip 是通过设定一个 Alpha 阈值（Alpha Cutoff，例如 0.5）来决定像素是否渲染的机制：

* **核心逻辑**：在 Pixel/Fragment Shader 中采样纹理的 Alpha 通道。如果 $\text{Alpha} < \text{Threshold}$，则使用 `discard`（HLSL）或 `clip()`（CG）直接**丢弃该像素**，不写入颜色缓冲区和深度缓冲区；如果 $\text{Alpha} \ge \text{Threshold}$，则当作**完全不透明的像素**处理。
* **特点**：它本质上渲染出的还是**不透明（Opaque）物体**，像素要么完全显示，要么完全被切除，不存在半透明渐变（不会产生 Alpha Blending 的混合计算）。

---

**2. 为什么不透明的东西会打断批次 (Batching)**

在图形渲染流程中，为了减少 CPU 发送绘制命令（Draw Call）的开销，通常会将属性相同的网格合并为一个批次（Batch）提交。

Alpha Clip 的物体虽然物理性质上被当做不透明处理，但无法轻易与普通的完全不透明物体（Opaque）打断合批，原因如下：

* **渲染管线顺序差异**：完全不透明物体通常开启深度写入（Z-Write）并使用简单的顶点/片元着色器；而使用 Alpha Clip 的物体需要额外的纹理采样和分支条件判断。
* **材质与 Shader 状态变化**：批次合并要求渲染状态（如使用的 Shader、Pass、变体 keywords 等）完全一致。使用了 Alpha Clip 的物体通常绑定了独立的 Shader 变体（如 `_ALPHATEST_ON`）。一旦状态切换（从普通 Opaque 切到 Alpha Clip），就会触发渲染状态更改，从而**打断批次**。
* **渲染队列（Render Queue）不同**：在很多引擎（如 Unity）中，Alpha Clip 物体会被单独划分为 `AlphaTest` 队列，排在普通 `Geometry`（不透明队列）之后、`Transparent`（半透明队列）之前渲染，队列的隔离直接导致无法合批。

---

**3. 为什么 Alpha Clip 性能不高**

虽然 Alpha Clip 避免了半透明混合的排序问题，但它对现代 GPU 硬件非常不友好，主要性能瓶颈在于以下几点：

* **破坏 Early-Z 优化（早期深度测试）**
* 现代 GPU 在运行 Pixel Shader 之前，会通过 **Early-Z** 提前判断像素是否被遮挡，若被遮挡则直接剔除，不再运行 Pixel Shader。
* 但当 Shader 中包含 `discard` 或 `clip()` 指令时，GPU 在运行 Pixel Shader 之前**无法预知该像素最终是否会被丢弃**。为了保证深度缓冲区的正确性，硬件必须**禁用 Early-Z**，迫使所有覆盖到的像素都完整执行一遍 Pixel Shader，大大增加了着色开销。


* **破坏 Quad-Overdraw 和像素并行（Warp/Wavefront 挂起）**
* GPU 以 $2\times 2$ 像素块（Quad）为单位并行执行片元着色器。如果 Quad 内的某几个像素执行了 `discard`，GPU 无法直接跳过该线程，而是需要屏蔽对应通道并等待整个 Quad 完成，这会导致**GPU 算力浪费**和**指令流水线停顿**。


* **过度绘制（Overdraw）与深度写入冲突**
* 草地通常密密麻麻、层层叠叠。由于无法高效利用 Early-Z 剔除被遮挡的后方草叶，光栅化阶段会产生严重的 Overdraw，反复采样纹理并计算着色。


草可以怎么优化？

坍缩三角形，假设草A只是一个三角形，那么把底部的两个顶点放一个位置，使用的时候再膨胀，这个时候膨胀的方向和屏幕投影方向对齐。就可以从前后左右看都是一样的，不会某个地方发现只有一个面。

草倒伏的效果怎么做？

引入一个场的概念，离角色越近场的力越大，草离中心位置相反方向倒伏。  倒伏可以是一个很简单的经验公式，力越大，pos向力的方向水平面分解方向偏移越多，为了看起来不像是拉长了草，还需要把末端位置降低，或者clamp一下
