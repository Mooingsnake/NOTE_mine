对于 `class`（引用类型），使用 `ref` **依然存在性能优化**，但优化的侧重点和 `struct`（值类型）截然不同。

---

**1. struct vs class 在 ref 传递时的机制差异**

* **对于 `struct**`：不加 `ref` 会复制**整个结构体的数据**；加上 `ref` 传递的是结构体的内存地址，省去了复制成本，同时允许修改原结构体。
* **对于 `class**`：不加 `ref` 复制的是**对象的引用（即指针，通常为 4 或 8 字节）**；加上 `ref` 传递的是**指向该引用的指针（引用自身的地址）**。

---

**2. class 使用 `ref` 时的性能影响**

* **避免指针/引用的复制**：虽然复制一个指针（8字节）开销极小，但在每帧需要处理成千上万个实体的 ECS 高频循环中，省去这 8 字节的压栈/复制操作依然能带来微小的 CPU 寄存器和指令优化。
* **内存连续性与缓存命中（CPU Cache）**：在高性能 ECS 框架（如 [Friflo.Engine.ECS](https://github.com/friflo/Friflo.Engine.ECS)）中，使用 `ref` 可以直接在底层组件数组的指针上进行原位迭代，避免产生任何额外的临时局部变量或装箱（Boxing），最大化利用 CPU L1/L2 缓存。

---

**3. 行为上的本质区别**

除了性能，`ref class` 和非 `ref class` 在**逻辑行为**上是有差异的：

* **非 `ref` (`Position position`)**：你可以修改对象的属性（如 `position.x = 10`），原实体会生效；但如果你在方法内部给它重新赋值（如 `position = new Position()`），**不会影响**实体身上原本引用的对象。
* **带有 `ref` (`ref Position position`)**：你不仅可以修改属性，还可以直接替换引用本身（如 `position = new Position()`），这会直接将 ECS 实体中存储的该组件引用**替换为新的对象**。
